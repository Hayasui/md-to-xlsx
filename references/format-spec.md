# 用研文档 → Excel：格式规范

本文件是用研交付物（需求梳理 / 问卷 / 访谈大纲三类表）的固化约定。
内容随项目变，**结构、列定义、样式不随项目变**；**每类的实例数可变**——
通常是一需求一问卷一大纲（三表），也可能再加一份有主持人访谈大纲（四表），
只出问卷不出大纲，或者问卷暂时只出中文版。

**总原则：这份表是给需求方（运营 / 产品）看的。**
写得简洁易懂，非必要呈现在文档里的文字一律删。需求方要看到的是
"要测什么、怎么筛人、问什么问题"，不需要知道"我们在哪个平台做、怎么录、怎么配置"。

> 需求梳理表松一档：它通篇都在讲研究设计，其中的分析口径一层算不算
> "非必要文字"，取决于这份表给谁——给组内同事可留，给需求方可省。见第〇节。

## 〇、删减清单（每次转换必做）

### 问卷表与大纲表：从严

| 删 | 例 |
|---|---|
| 平台与执行信息 | 平台名、测试形式（Unmoderated / Think-Out-Loud）、录屏录音方式、"无人主持"、Zoom / 共享屏幕说明 |
| 内部标注 | 「（本研究的核心品类）」「（硬性门槛题）」 |
| 不影响作答的括号 | 「手机（安卓 / 苹果）」→「手机」 |
| 标题行与说明行 | 「【编号】项目名 · …（中英对照 · 留档版）」、页面说明行 |
| 研究落点 / 内部备注 | 一律不进表（大纲「目的」列除外，且要改写成平实中文） |
| 设计过程稿的论证部分 | 方案对比、设计理由、编码流程、桌面研究附录、版本变更记录（见下「输入若是过程稿」） |

保留：玩家在平台上真正看到的内容、影响作答的括号（「（可多选）」）、
问卷表的「问卷逻辑」列。

### 需求梳理表：松一档

保留：研究目标与研究假设、研究方法、样本条件、单场时长、目标国家、交付物、分析口径。
后四项是否保留，看这份表给谁看。

**「本表为留档版，编号仅用于内部沟通」这类说明行**：加还是删由用户定，
不同项目取舍不同（它曾是用户主动要求的，后来又被删掉）。默认按"删"处理，
但报出来让用户拍板。

### 输入若是过程稿

真实项目里，输入常常不是成品稿，而是一份还在迭代的设计文档——结构总览、
方案对比、设计理由、编码方案、桌面研究附录都在里面，真正的问卷只占一节。
这时先做一次提取，只把定了的那版问卷取出来，以下留在 md：

结构与流程总览 · 方案对比与取舍 · 设计理由与论证 · 编码与分析方案 ·
桌面研究附录 · 待确认标记 · 版本变更记录

判断标准：**这句话是玩家会看到的、需求方要判断的，还是设计者自己要想清楚的**。
第三类全部留在 md。取完把"哪些进了表、哪些没进"列给用户过一眼。

## 一、三类表的固定结构

表分三类，**每类可放任意多个实例（含 0 个）**：需求梳理 / 问卷 / 访谈大纲。
不要假设必然是"一需求一问卷一大纲"。
样式（列定义、字体、行高、打印）不随实例数变，只有工作表数量变。

### 表格 1 · 需求梳理

- **语言**：纯中文，不出英文
- **列**：`项目 | 序号 | 内容`（3 列，宽度 17 / 9 / 112）
- **标签页颜色**：深青灰 `334E5C`
- **无标题行、无说明行**，表头直接落在第一行

内容行的类型：

| 类型 | 说明 |
|------|------|
| `kv` | 标签 + 单段内容（项目、调研背景、研究方法、单场时长、目标国家） |
| `kvlist` | 标签 + 多个「子标签 / 内容」行（样本条件：游戏、性别、年龄、设备、参与意愿） |
| `numlist` | 标签 + 多个「序号 / 内容」行（研究目标：每个 RQ 一行） |
| `muted` | 灰色显示，用于「待定」（样本量、素材链接） |

**研究目标**每格放两行：第一行是「一句话落点」，第二行是「研究假设：……」。
这是全表唯一一个单元格内放两段文字的地方，因为落点和假设是一对，拆开反而难读。

**研究目标不用 `【】` 标签**——四项已由「序号」列（1/2/3/4）承载，再加标签是重复。
（访谈大纲的「目的」列同样不用 `【】`，见下。）

**推荐字段顺序**：项目 → 调研背景 → 核心验证对象 → 研究目标 → 研究方法 →
单场时长 → 样本条件 → 目标国家 → 样本量 → 素材。
后三项以外可按项目增删（如模块构成、交付物、分析口径），顺序保持不变。

### 表格 2 · 问卷

- **语言**：中英逐行并列（`survey`）或纯中文（`survey_cn`），见下表
- **标签页颜色**：蓝灰 `3F6E8C`
- **内容**：开场说明 → 各部分题目 → 结束语
- **只放玩家可见内容**：内部备注、研究落点、招募审核备注一律不进表

两种列规格：

| 场景 | 列 | 宽度 |
|---|---|---|
| 中英并列（`survey`） | `模块 | 题型 | 题号 | 中文 | English | 问卷逻辑` | 17 / 11 / 8 / 54 / 54 / 27 |
| 纯中文（`survey_cn`） | `模块 | 题型 | 题号 | 中文 | 问卷逻辑` | 17 / 11 / 8 / 80 / 36 |

纯中文版用在"中文定稿在先、英文版尚未制作"的场景，这是流程的常态而非例外。
英文版做好之后换成 `survey`，内容一行不动，只是多出一列。

**「模块」列**（最左列，2026-09-11 起）：记录这道题属于哪一组，值取自内容区的
`("section", "模块名")` 行，按题纵向合并。它是表的导航，不是玩家可见内容。
一个 `section` 行都没有时生成脚本直接报错，把题干全列出来让人先分类——
模块名按题目性质取（「基础信息收集」「付费与留存」），覆盖哪些题号要跟用户确认；
md 的段落名能直接用就沿用，那是首选。

**表名跟随问卷用途**：甄别问卷叫「玩家筛选问卷」，满意度或偏好类问卷叫
「题材偏好问卷」「满意度问卷」等。不要固定写「玩家筛选问卷」。

**「问卷逻辑」列**：记录题目之间的跳转与因果关系，记在**触发它的那一行**上。
列名统一，语义由内容决定：

| 场景 | 写法 |
|---|---|
| 甄别问卷的硬门槛 | `终止`（红色加粗，样式 key `stop`），照 md 写 |
| 跳过整个板块 | `跳转到 Q6` |
| 最后一个板块跳过 | `本模块结束` |
| 互斥选项 | `与其余色调选项互斥，不可同时选中` |
| 触发文本框 | `需填写文本（必填，≤20 字符）` |

三条细则：

- **不写在被依赖的题目上**。历史踩坑：早先把「Q4 未勾选跳过项」写在 Q5 的格子里，
  读者要反推是哪条路径导致的隐藏，配置时也容易漏。
- **依赖型题目不写条件**（吸引点题之所以出现，由上一条跳转隐含）。
- **数目标注仍写在题干里**（「最多选 3 项」约束的是同题内的选择数量）。

**填写问卷的人看不到这一列**，它是给配置问卷的人看的，不必为玩家可读而改写措辞。

**`field` 行**：并列在选择题下的补充输入（「用一句话说说为什么」），
与上一题共用题型与题号。前提是平台支持"选择题 + 附加文本输入"；
不支持时要另立题号并整体顺移，生成交付表之前先问清。

**题型与标记**：
- 题型列用**中文简述**（见下节「题型术语映射」）
- 默认全部必答，因此**不单独设「必答/选答」列**；若某题非必答，写在题型列里
  （`简答（非必答）`），不在题干末尾缀「（选填）」

**题号**：连续数字，`Q1` 式，**不用 `Q4a` / `Q4b` 分支写法**。
一道选择题附带文本框是一道题，不拆号；真要拆就整体顺移。

**选项排布**：每个选项单独一行。模块、题型两列在该题所有选项行上**纵向合并**，
只在题干行出现一次；**题号列不合并**——选项行上要写该题的选项序号（1、2、3……），
合并了就只剩首行有值。读表的人扫一眼这一列，就知道这道题有几个选项。

**中英并列写在同一格**：中文里的单字类别名（「红」「紫」）互相容易混淆，
这类选项可以写成 `红（Red）`，比另开一列干净。
**不建议给纯中文表补空的中英列**——需求方看到空列会追问"这两列为什么是空的"。

### 表格 3 · 访谈大纲（可有多份）

- **语言**：中英逐行并列
- **列（六列版）**：`模块 | 目的 | 题号 | 题型 | 中文 | English`
  （宽度 19 / 21 / 8 / 14 / 50 / 50）
- **列（八列版，有主持人版常用）**：
  `模块 | 目的 | 题号 | 题型 | 中文 | English | 追问方向 | 观察记录点`
  （宽度 19 / 21 / 8 / 12 / 44 / 44 / 36 / 36）
- **标签页颜色**：墨绿 `6B8E7F`；多份时依次取 `6B8E7F` / `7A6A9B` / `8E7F6B`
- **内容**：Task A（Instruction + Navigation）→ Task B（Page 1-9）
- **表名跟随访谈形式**：`无主持人访谈大纲` / `有主持人访谈大纲`，
  不固定写「访谈大纲」（那样会丢掉形式信息）
- **多份并存的场景**：各自独立成表，**「目的」列逐题写同一个词**。
  生成后跑一次逐题比对，不一致就统一。
  **不建议给六列版补两列空列**凑成同构——拿六列共有的部分对照即可。

**八列版多出的两列**，对应有主持人版 md 的三栏式：

| md 里的栏 | 进 xlsx 哪一列 |
|---|---|
| 提问话术 | 中文 / English（题干位） |
| 追问方向 | 追问方向列，每行一条追问 |
| 观察记录点 | 观察记录点列 |

用了 `fu` / `obs` 行却没在 `columns` 里声明对应列，脚本会当场报错——
这是刻意设计的，避免内容被静默丢弃。

**「模块」列**：纵向合并显示页面名（`Task B · Page 5`），随页面区块变化。

**「目的」列**：写平实中文，从 md 的「研究落点」改写。**不出现 RQ 编号、
不出现「【】」自造标签**。

**禁止事项**（这是从 2608 那份文件继承教训）：
- 严禁把「追问」「内部备注」塞进题干单元格
- 严禁在单元格内堆砌大段文本
- 严禁自造标签（如「【玩法定位与偏好】」）
- 一格里只放玩家真正看到的那句话

**页面引导语**：单独占一行，用浅底标出（样式 key `key` + 引导语正文）。
因为玩家在平台上确实会看到它。

**特殊题型**：
- **Matrix**：题干行 → 量表说明行（`scale` 样式）→ 每个陈述一行
- **Ranking**：题干行 → 每个待排序项一行

## 一·五、题型术语映射

平台题型名是 UserTesting 的内部定义，需求方不需要认识。**题型列一律中文简述**：

| 平台原名 | xlsx 里写 |
|---|---|
| Multiple Choice（单选） | 单选 |
| Multiple Choice（多选） | 多选 |
| Verbal response | 口头回答 |
| Open text / Short answer | 简答、填空 |
| Matrix | 矩阵 |
| Ranking | 排序 |
| Rating scale / NPS | 打分 / NPS |

三条细则：

- **NPS 不翻译**——约定俗成的用法，写「净推荐值」反而增加理解成本。
- **题型列不标区间**——写「打分」即可。区间由题干和量表标签承载
  （「1 分最低，10 分最高」）。
  历史踩坑：md 题型标 `Rating scale · 0-10`，题干写「1 分最低，10 分最高」，
  实际是 1-10——题型标注与题干打架。区间只在一处写就不会冲突。
- **非必答写在题型列**——`简答（非必答）`。不在题干末尾缀「（选填）」，
  也不单开一列；后者会让需求方追问"这一列怎么全是空的"。

题号用 `Q1` 而非「题 1」（更短，且与问卷表统一）。**连续数字，不用 `Q4a` 分支写法。**

## 二、通用样式约定

| 项目 | 值 |
|------|-----|
| 中文字体 | **微软雅黑** |
| 英文字体 | **Aptos**（Office 2024+ 默认字体） |
| 正文字号 | 10pt |
| 标题行 | 12pt 加粗白字 + 深色底，行高 30 |
| 说明行 | 9pt 灰色斜体 + 浅底（「本表为留档版，编号仅用于内部沟通」） |
| 表头行 | 10pt 加粗白字 + 中灰底，居中 |
| 分节行 | 10pt 加粗深色字 + 浅蓝底（开场说明、第一部分…、结束语） |
| 正文 | 10pt，顶端对齐，自动换行 |
| 边框 | 细线 `DCE3E8`；每个题目区块首行用中粗线分隔 |
| 网格线 | 关闭 |
| 冻结 | 首行表头（`A2`） |
| 行高 | 按「字符显示宽度 ÷ 列宽」估算行数 × 15.2 + 5，夹在 24–300 之间 |
| 缩放 | 100% |

### 字体按列切换（重要）

中英分列，字体按**列**决定，不是按内容：

- 中文列（表格2 的 C 列、表格3 的 E 列）→ 微软雅黑
- 英文列（表格2 的 D 列、表格3 的 F 列）→ Aptos
- 表格1 整表中文 → 全用微软雅黑
- **跨列合并的单元格**（标题行、分节行、说明行）→ 一律用微软雅黑

判定逻辑：只有「单列且该列是英文列」时才用 Aptos。

**Aptos 回退风险**：Aptos 是 Office 2024 / Microsoft 365 的新默认字体，
部分机器（尤其是旧版 Office 或 WPS）未安装，Excel 会回退成默认字体。
如需兼容旧环境，把脚本里的 `FONT_EN` 改成 `Calibri` 或 `Arial`。

### 打印设置（留档、导出 PDF 用）

- 横向（landscape）
- 缩放到一页宽（`fitToWidth=1`，高度不限）
- 每页重复表头行（第 1 行，表头直接落在首行）
- 页边距 0.4 英寸
- 页脚居中显示「第 X 页 / 共 N 页」

**行高估算**：中文字符按宽度 2 计，英文按 1 计。
可用宽度 = 列宽总和 − 2.5。这是经过验证的模型，与 WPS 实际渲染接近。

## 三、题号与文件命名

- **保留题号**（`Q1`-`Q9` / `Q1`-`Q28`），**连续数字**，
  不用 `Q4a` / `Q4b` 分支写法，但**不设「本表为留档版」说明行**
- **文件名**：`【YYMM】项目简称.xlsx`
  - `YYMM` = 当前年月。例：2026 年 9 月 → `【2609】`
  - 生成前扫一遍目录里已有的 `【NNNN】` 文件，默认取最大值 +1，向用户确认
  - 用户可能用非日期编号（如 `【K3P】`），所以候选值要请用户点头，不要直接采用
- **版本管理**：生成的原件**不带版本后缀**；用户后续手动修改用 `v1`、`v2` 后缀区分

## 四、中英对照规则

1. 表格 1 只出中文。
2. 表格 2、3 每行中英并列：中文列在前，English 列在后。
   **只有中文稿时**，表格 2 用 `survey_cn` 出纯中文版，不补空的中英列。
3. **版本主从**：中文 md 是**源头**，英文 md 是它的**本地化产物**，xlsx 是**忠实渲染**。
   - 中文列照中文 md，英文列照英文 md，各自如实呈现。
   - xlsx **不参与版本判定**——中英不一致时只**报出来**，由用户判断原因，不自行选一个。
4. 生成后**必须列出中英不一致之处**提醒用户。历史踩坑：题 17 英文版
   「2-3 words」vs 中文版「1-2 个词」；Question Map 里 "Fairy-tale" 应为 "Carnival"。
5. **中英同格的例外**：中文单字类别名（色名、题材名）容易互相混淆时，
   可以写成 `红（Red）` 放在同一格。这是排版上的处理，不改变中英主从关系。

## 五、生成后的必查项

`build_research_xlsx.py` 保存后会自动调用 `validate_xlsx.py` 校验，无需手动跑。
校验脚本先在同目录找，找不到会到技能安装目录去找；两处都没有才会跳过，
并明确打印提示。**看到"跳过自动校验"就要把文件复制过去重跑**——
「已生成」三个字不含任何校验结论。

校验项包括：

1. **行高是否够**：长英文题干最容易出问题
2. **合并是否重叠**：重叠会导致文件异常
3. **Markdown 残留**：`**`、`*` 是否清理干净
4. **字体是否正确**：中文格是否误用了 Aptos
5. **打印设置**：是否横向、是否设了重复表头
6. **冻结与网格线**：是否冻结首行（`A2`）、是否关闭网格线

需要单独校验已有文件时：

```bash
python scripts/validate_xlsx.py <文件.xlsx>
```

手动补充确认：

- 题号是否完整（问卷表查 Q1-Qn，每份大纲各查一遍；两版大纲的题号应一一对应）
- 内部内容是否残留（搜「研究落点」「内部备注」「RQ1」「人工复核」）
- 中英一致性（两侧题数、选项数是否相同）
- **问卷逻辑是否记在触发它的那一行**，而不是写在被依赖的题目上
- **同质信息写法是否统一**：同一类标注是否一处留一处删、模块名前缀是否一致、
  题型列是否中英混用、同一层级的称呼是否只有一种说法
  （详见 SKILL.md「一致性检查」）

## 五·五、用户改过 xlsx 之后怎么回写

用户可能在腾讯文档 / Excel / WPS 里直接改表格内容。**不要请他复述改了哪里**：

```bash
# 用当前脚本另生成一份到临时文件（--no-backup 避免污染 _backup/）
python _build_<项目>.py _tmp_orig.xlsx --no-backup
```

再用 openpyxl 逐格 diff，差异格就是他的改动。逐处报给他确认，并同步进脚本与 md——
不同步的话，下一次重新生成就会把修改覆盖掉。

判断文件被什么工具动过，读 `docProps/app.xml` 的 `<Application>`：
`Tencent office` 是腾讯文档，`WPS` 是 WPS，`openpyxl` 是本脚本写的。
比对以**内容**为准，样式差异（行高、字体被工具重算）不必追究。

## 六、覆盖策略（重要）

用户可能在 WPS / 腾讯文档 / Excel 里手动改过 xlsx。**不同工具带来的副作用不同**：

| 工具 | 副作用 |
|---|---|
| WPS 保存 | 重算行高（值更紧凑，如 15.6 / 30 / 45），脚本算的更宽松（24 / 39 / 54.5） |
| 腾讯文档另存 | 字体换成等线、丢失冻结窗格与打印设置、多出空列、行高重算 |

内容和样式一致，但排版观感会变。因此：

- 生成前若目标文件已存在，脚本**自动备份**到 `_backup/` 目录
  （文件名形如 `原名_20260908_185528.xlsx`）
- 用 `--no-backup` 参数可跳过备份
- 若用户已手动修改过，**优先保留用户版本**，只把改动同步到脚本和 md 源
- 用户的手动修改版本用 `v1`、`v2` 后缀命名，与生成的原件区分
- **样式基线不跟工具走**：中间被什么工具打开保存过都不影响，
  重新生成的样式一律回到脚本里的固化规范
- **判断被什么工具改过**：读 `docProps/app.xml` 的 `<Application>`，
  腾讯文档是 `Tencent office`，openpyxl 是 `Microsoft Excel Compatible / Openpyxl x.x.x`

## 七、QOL 设计说明

脚本内置的便利功能（无需额外配置）：

| 功能 | 说明 |
|------|------|
| 自动备份 | 目标文件存在时自动存一份到 `_backup/` |
| 自动校验 | 保存后立即跑校验并打印问题清单 |
| 字体分列 | 中文列微软雅黑、英文列 Aptos，跨列合并用中文字体 |
| 打印预设 | 横向、一页宽、重复表头、页脚页码 |
| 行高自适应 | 按内容估算，避免文字被裁切 |
| 区块分隔线 | 每道题首行加中粗上边框，视觉分组 |
